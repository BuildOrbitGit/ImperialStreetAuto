## Overall Impression

A solid, opinionated design with genuine character — the palette and typographic choices are brave and specific. Real information shows up exactly where it should. The single biggest opportunity: strip the numbered section markers. Right now, a page with real personality is framed by the AI scaffold that signals "generated." Fix that one thing and the authenticity the content delivers will land cleanly.

## What's Working

1. **The palette is genuinely distinctive.** Electric navy + cornflower blue breaks from the warm-neutral monoculture without defaulting to dark-mode cliché. It reads as a craftsman's reference, not a franchise template.

2. **Specificity is everywhere.** Real prices ($34.99 oil change, $89.99 inspection), real address, real hours, and the live open/closed status widget. The status widget is a particularly strong touch — it answers "are they open right now?" without the user doing mental math.

3. **Mobile-first CTA execution.** The FAB (floating action button) is correctly placed and always reachable. Utility bar phone number plus the FAB creates appropriate redundancy for the most important conversion action on a neighbourhood shop page.

## Priority Issues

**[P1] Numbered section markers on all six sections**
- **What**: `<span class="section-num">01 · Services</span>` through `06 · Find the shop` appear above every content section heading.
- **Why it matters**: This is the clearest AI-scaffold tell on the page. Numbers earn their place when a section *is* an actual ordered sequence — a checkout flow, a 3-step process. Section labels on a scrollable marketing page are not a sequence; the numbers add noise without carrying meaning.
- **Fix**: Remove the `section-num` `<span>` elements. The section headings stand on their own. If a visual cadence element is needed, use something that grows from the brand (a `--red` horizontal rule, a single letterform, a tool-mark) rather than sequential digits.
- **Suggested command**: `/impeccable polish index.html`

**[P1] Contrast failure: muted text on blue backgrounds**
- **What**: `--muted` (#5a6385) used on cornflower-blue section backgrounds (approximately #9bbae8). Estimated contrast ratio: ~2.5–3:1. WCAG AA requires 4.5:1 for normal text.
- **Why it matters**: Mobile users in sunlight and Sam with browser zoom will struggle to read secondary text in blue sections. PRODUCT.md explicitly flags this concern. This is an accessibility failure, not just an aesthetic preference.
- **Fix**: On blue-background sections, replace `--muted` with `--ink` (#0a1736) for full contrast, or `rgba(255,255,255,.82)` or higher for a "muted" white variant. The white overlays used elsewhere in the CSS are already the right direction.
- **Suggested command**: `/impeccable audit index.html`

**[P1] Reveal animations gate content at opacity: 0**
- **What**: `.reveal { opacity: 0 }` sets most sections invisible by default. IntersectionObserver applies `.visible` to trigger the fade-in. If JS is slow, blocked, or the observer doesn't fire (hidden tab, throttled CPU, old device), sections stay invisible.
- **Why it matters**: "Reveal animations must enhance an already-visible default" — this inverts that. On slow mobile connections, the exact device the shop's stressed customer is on, sections can render blank. Also breaks search engine visibility for below-fold content.
- **Fix**: Invert the pattern: default to `opacity: 1`. JS adds a `.reveal-ready` class to `<body>` when the observer is set up, and CSS scopes the animation: `.reveal-ready .reveal { opacity: 0; transform: translateY(20px) }`. No JS = full page. JS = smooth entrance.
- **Suggested command**: `/impeccable animate index.html`

**[P2] Layout property animations causing jank**
- **What**: `transition: padding` on `.service-row` (line 887) and `transition: max-height` on `.faq-a` (line 1210) both animate layout properties.
- **Why it matters**: Layout thrash on every FAQ click and service hover. Visible jank on mid-range Android phones.
- **Fix**: For FAQ: replace `max-height` animation with `grid-template-rows: 0fr → 1fr` transition — GPU-composited, smooth. For service row: use `transform: translateY(-4px)` on hover instead of padding change, or remove the transition.
- **Suggested command**: `/impeccable animate index.html`

**[P2] Review stars missing from HTML**
- **What**: `.review-stars` CSS class exists and is styled, but review `<article>` elements contain no star elements. The rating area renders empty.
- **Why it matters**: A rating number "5" with no visual stars reads as a number, not a score. Jordan and Casey will miss that these are 5-star reviews. Social proof is a primary trust signal for the shop.
- **Fix**: Add five `<span aria-hidden="true">★</span>` elements inside each `.review-stars` container, plus `<span class="sr-only">5 out of 5 stars</span>` for accessibility.
- **Suggested command**: `/impeccable polish index.html`

## Persona Red Flags

**Jordan (First-Timer)** — lands from "auto repair Burnaby" search, stressed, on mobile.
- Trust strip with "since 2010" and walk-in welcome is visible immediately. Strong.
- Scrolls to reviews. Sees "5" with empty star area — looks like a broken number, not a rating. Confidence drops at the exact moment social proof should land.
- Reveal animation: older Android Chrome takes 1-2 seconds to parse the JS bundle. Entire page below the hero is invisible during that window. On a stressed visit, blank sections look like loading failure — Jordan may bounce before content appears.

**Casey (Distracted Mobile User)** — one-handed on SkyTrain.
- FAB call button: correct thumb placement, always visible. Strong.
- Switches to check a message mid-scroll. Returns. IntersectionObserver may not have fired for sections Casey missed — content still invisible.
- FAQ: taps to expand "Do I need an appointment?" — `max-height` transition stutters on lower-end device. Minor but adds friction.
- Star ratings invisible: Casey sees "5" and scrolls past without registering it as a 5-star review.

**Sam (Accessibility-Dependent)** — keyboard and screen reader user.
- No skip-to-content link. 15+ tab stops through utility bar, nav, and hero before reaching page content.
- `.reveal { opacity: 0 }` is in the accessibility tree: screen reader reads invisible text aloud while the visual page looks blank. Disorientating.
- `--muted` text on blue backgrounds: Sam at 150% browser zoom — background tints shift, contrast worsens.
- Review articles: screen reader announces "5" with no star context. Needs `aria-label="5 out of 5 stars"` on the rating element.

## Minor Observations

- **Three near-identical reds in specials card** (`#b01a1a`, `#c82020`, `#a01616` at line 681): consolidate to one hover-state token.
- **`border-radius: 8px` at line 724** not in DESIGN.md radius scale: document as `--radius-sm` or replace with nearest documented token.
- **`#e6a521` amber/gold for review stars** (lines 1132, 1149): not in DESIGN.md. If stars are shipping, add `--star` token.
- **Hero title ceiling**: `clamp(56px, 9vw, 132px)` hits 132px at 1467px viewport. DESIGN.md ceiling rule is 96px. The heading is strong at 96px; 132px risks poster-shouting at wide desktop.
- **`#4adf86` (open) / `#ff6666` (closed) status colors**: intentional and correct, but undocumented. Add as `--status-open` / `--status-closed` tokens in DESIGN.md.
- **`rgba(0,0,0,.1/.2/.3)` shadow overlays scattered throughout**: create 2-3 named shadow tokens rather than repeating alpha values.
